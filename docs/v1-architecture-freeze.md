# WhatMint V1 架构冻结说明

这份文档用于确认 WhatMint 第一版产品的核心架构已经达到“可用于产品搭建”的状态。

结论先行：

- V1 的 OS 与核心对象层已经足够支撑当前第一版业务功能。
- 后续工作的重点不再是继续抽象 OS，而是基于真实 IP、真实关系和真实场景做产品级搭建。
- 除非出现明显阻塞，不再进行 OS 层的大规模重设计。

## 1. 冻结目标

V1 冻结的不是“所有代码都不会再改”，而是下面三件事进入稳定基线：

- 世界模型已经足够稳定，可以承载首页、创作中心、内容中心、商城、用户中心和官方管理端。
- OS / 应用边界已经足够清楚，可以支撑多个轻应用接入同一套运行内核。
- 关系化、情绪化、实体化、轻智能化体验已经有统一承载路径，不需要每个应用单独发明机制。

## 2. 第一版业务范围

当前第一版产品主要围绕以下业务面展开：

- 用户端：首页
- 用户端：创作中心
- 用户端：内容中心
- 用户端：商城
- 用户端：用户中心
- 管理端：官方配置、官方内容、官方资产与应用管理
- 轻应用生态：多个 IP 对应多个数字空间，并通过关系和事件产生联动

这套产品的目标不是单一内容播放系统，而是：

> 通过多个轻应用数字空间和对应 IP 的联动，形成微智能生态，最终带来关系、情绪、实体化、智能化的深度体验。

补充冻结判断：

- 首页也应按“数字空间”而不是传统营销落地页理解。
- 首页负责呈现用户进入 WhatMint 世界的总入口：世界状态、IP 关系、可进入空间、官方 IP 和创作入口。
- 资产页应从“资产列表管理”升级为“用户拥有 IP 实例的数字空间入口”，像进入一个轻量游戏房间一样查看 IP 实例的状态、内容、事件和关系。

## 3. 核心对象层

V1 的核心对象层已经收敛为 8 个核心对象：

- `users`
- `ip_definitions`
- `application_definitions`
- `content_definitions`
- `ip_instances`
- `content_instances`
- `resources`
- `events`

它们分别回答：

- 谁存在于这个世界
- 什么 IP 可以存在
- 什么应用能力可以存在
- 什么内容能力可以存在
- 用户真正拥有什么实体资产
- 用户真正拥有什么内容资产
- 内容最终依赖什么资源运行
- 世界里发生过什么高价值事实

这 8 个对象已经足以支撑当前第一版业务功能，不再继续扩张核心概念表。

## 4. 关系与 supporting 层

除 8 个核心对象外，允许存在 supporting tables，但它们不能形成第二套业务真相。

当前高价值 supporting 层包括：

- `operations`
- `event_consumptions`
- `meaningful_states`
- 核心对象之间的连接表

这些对象的职责是：

- `operations`：记录原始动作事实
- `events`：记录提炼后的有意义事实
- `meaningful_states`：记录沉淀后的产品状态
- `event_consumptions`：记录事件被谁消费、以什么 skill 消费、产生了什么结果

此外，多对多关系通过连接表表达，例如：

- `ip_definition_application_links`
- `application_content_definition_links`
- `ip_instance_content_instance_links`
- `content_instance_resource_links`
- `ip_definition_relation_links`

这里已经满足第一版所需的“实体、内容、应用、资源、关系矩阵”表达能力。

## 5. OS 运行主链

V1 运行主链已经明确固定为：

`operation -> event -> state/context -> skill -> action/content result -> app assemble`

对应职责如下：

- `operation`：应用上报发生了什么动作
- `event`：OS 判断这个动作何时开始具有业务意义
- `state`：OS 沉淀当前用户 / 物 / 世界的状态
- `context`：运行时为当前对象拼装状态、已解锁能力和内容修饰信息
- `skill`：应用声明自己对哪些事件或状态有响应能力
- `action`：OS 执行生成内容、记录消费、绑定结果等动作
- `assemble`：应用最终决定如何把这些结果表达为用户体验

这条主链已经足够支持第一版的“微智能联动”需求。

## 6. OS 与应用边界

V1 的边界已经基本成立：

### OS 负责

- 身份与对象解析
- 权限与路由策略
- 原始操作记录
- 事件生成与事件账本
- 状态沉淀
- Runtime Context 拼装
- Skill 触发与事件消费
- 内容结果生成与回填
- Studio Shell 与统一接入能力

### 应用负责

- 角色设定
- 内容语气
- 叙事节奏
- 世界观表达
- 视觉与互动风格
- 内容模板与体验装配

这意味着：

- 应用不再自己判断复杂全局条件
- 应用不再各自发明联动协议
- 应用只声明能力与表达方式
- OS 负责把“世界如何运转”稳定下来

## 7. 当前范式验证

以“纸巾小狗 -> 耳机小姐联动”为例，当前 V1 已经验证了这套范式可以成立：

- 纸巾小狗触碰上报为 `operation`
- OS 将高频触碰提炼为 `event`
- `event` 投影出 `meaningful_states`
- 耳机小姐声明自己订阅该类事件
- OS 记录 `event_consumptions` 并生成联动内容结果
- 耳机小姐应用在 `runtime_context` 中读到内容修饰结果并完成表达

这说明当前 OS 不再只是抽象设想，而已经具备真实业务承载能力。

## 8. 对第一版业务的支持判断

当前架构已经可以支持以下第一版能力：

- 商城展示 IP、详情、官方默认体验内容
- 创作中心统一承载官方创作与用户创作
- 内容中心承载内容资产查看与管理
- 用户中心承载账户、资产、事件与行为结果查看
- 管理端承载官方 IP、应用、内容与配置管理
- 多个轻应用通过统一 OS 范式接入
- IP 之间通过官方关系矩阵和事件联动形成微智能生态
- 首页与资产页围绕“数字空间”组织，而不是围绕单纯导航和列表管理组织

我的判断是：对第一版业务来说，核心架构已经成熟到足以进入产品建设阶段。

## 8.1 数字空间页面范式

数字空间不是新的核心表，而是一种页面组织范式：

> 一个数字空间 = 某个用户视角下，对 IP 实例、内容、事件、状态、关系和可进入应用的聚合呈现。

对应页面职责建议：

- 首页：全局数字空间，总览 WhatMint 世界正在发生什么。
- 商城 / IP 详情：定义层空间，展示一个 IP 是什么、它和谁有关系、它如何被带回现实。
- 资产页：实例层空间，展示用户真正拥有的 IP 实例、默认内容、状态、事件和可进入应用。
- 内容详情页：内容资产空间，展示一个内容实例内部的节点和资源。
- 创作中心：内容创建与修改流程编排，不承载长期内容管理。

这个范式让 WhatMint 从“内容平台 + 商城”转向“可触碰 IP 世界”，更贴近关系情绪实体化的产品北极星。

## 9. 后续策略

从 V1 冻结开始，后续策略调整为：

- 不再进行 OS 层的过度抽象
- 不再为了未来可能场景继续增加核心概念
- 不再为了“更通用”而拆出新的大系统

后续工作的重点转为：

- 做真实 IP
- 做真实关系矩阵
- 做真实官方内容
- 做真实场景联动
- 做用户体验闭环
- 用产品验证架构，而不是继续纸面扩展架构

## 10. 仍值得持续关注的高收益事项

虽然不再做重大架构重设计，但仍有几类高收益工作值得继续：

- 把新增轻应用继续按统一范式接入 OS
- 逐步收敛 `application_definitions` 与代码 manifest 的对应关系
- 完善 `operation / event / state / consumption` 的查看、诊断与幂等治理
- 持续清理“旧特例逻辑”，避免它们成为第二套运行机制
- 验证首页与资产页的数字空间体验，而不是继续把它们做成传统列表页

这些工作属于接入治理和运行稳定性，不属于再次抽象核心世界模型。

## 11. 最终结论

V1 到这里可以正式认为：

- 核心对象层已基本冻结
- OS 主链已基本成立
- OS / 应用边界已基本清楚
- 第一版业务功能已有稳定承载基础

因此，WhatMint 现在可以把主要精力切换到产品级搭建：

> 用真实 IP、真实关系、真实场景，把微智能生态真正做出来。
