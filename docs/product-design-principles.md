# WhatMint 产品设计规范

## 这份文档回答什么

产品宣言回答：WhatMint 为什么存在。

产品设计规范回答：一个新应用该不该做。

WhatMint 后续会不断长出新的自营轻应用、实体 IP、创作工具和商业入口。为了避免产品矩阵变成 NFC 小工具合集，每个新应用在立项前都要先回答这份规范里的问题。

这不是限制创意，而是保护 WhatMint 的产品语言：让不同应用像同一个现实世界 UI App 里的场景入口，而不是被功能拼在一起。

最新 IP 体系探索见：[ip-system-exploration.md](ip-system-exploration.md)。新应用判断时，应优先确认它是否符合“现实动作 x 情绪需求 x 轻交互 x 魔法瞬间”的微童话原则。

## 一句话立项语法

任何创意都应该先用一句话描述：

物件 x 行为 x 意义。

例如：

- 行李箱 x 出发 x 开启旅程。
- 门票 x 收藏 x 留住瞬间。
- 礼物 x 拆开 x 表达心意。
- 摆件 x 陪伴 x 安放心情。

如果一个创意不能在十秒内说清楚这句话，就先暂缓开发。

## 1. 物性原则

先问：这个体验是否真的只能发生在这个物件上？

WhatMint 的入口是 NFC，但主角不是 NFC。主角是现实物体。

如果体验换成任意贴纸、二维码或 App 首页仍然成立，说明它还没有找到物性。

判断标准：

- 5 星：体验强依赖这个物件。没有这个物件，意义明显下降。
- 3 星：物件能增强体验，但不是不可替代。
- 1 星：任意 NFC 都能做，物件只是入口。

低于 3 星的创意，不建议进入开发。

示例：

- 行李箱 x 出发：成立，因为行李箱天然跟随旅程移动。
- 门票 x 演唱会：成立，因为门票天然承载一次事件和收藏。
- 天气 x 任意 NFC：不成立，因为直接打开天气 App 也可以。

## 2. 行为原则

先问：用户为什么会拿起、触碰或靠近这个物件？

行为说不清楚，产品定义通常也说不清楚。

常见行为包括：

- 出发。
- 拆开。
- 收藏。
- 陪伴。
- 喝水。
- 睡前。
- 送出。
- 回来。
- 想念。

触碰不是抽象动作，它应该嵌在一个真实行为里。用户不是为了“使用功能”触碰，而是在某个生活动作中顺手打开物的数字空间。

## 3. 单一价值原则

一个应用只完成一个价值，只回答一个具体场景里的问题。

不要把纪念、AI、聊天、音乐、相册、地图和社交都放进一个轻应用。轻应用越轻，越需要价值锋利。

示例：

- 纸巾小狗：这一刻需要怎样被轻轻安慰？
- 桌面秘境：我的桌面能否短暂出现另一个空间？
- 未来的纪念、传信、清单或回应类应用：必须先重新回答自己的单一人生问题，再按新核心范式接入。

如果一个应用需要回答多个问题，优先拆成多个应用，或把通用能力下沉到 OS。

## 4. 微童话原则

先问：这个应用是否让一个容易被忽略的小瞬间值得被认真对待？

WhatMint 不创造逃离现实的幻想世界，也不把轻应用做成泛工具集合。它让现实生活里的小动作多一点点魔法。

判断标准：

- 它守住的是一个具体小瞬间，而不是一个宏大主题。
- 它的核心动作可以被用户立刻记住。
- 它带来的情绪变化清楚、克制、不需要复杂解释。
- 它允许用户重新解读和二创，而不是只能按官方说明使用。

示例：

- 纸巾小狗：递出纸巾，让难过和关心被接住。
- 喝彩便签：划掉任务，为微小努力放礼炮。
- 装装：把物品装进去，让准备和出发更安心。
- 桌面秘境：进入桌面小地方，让疲惫时有一个可停留的微空间。

## 5. 实体不可替代性原则

先问：没有这个实体，这个体验还成立吗？

如果答案是“直接打开 App 就可以”，那这个实体只是二维码，不是 WhatMint 想做的东西。

实体不可替代性来自：

- 物体天然出现在那个场景里。
- 物体被用户拥有、携带、赠送或收藏。
- 物体能让数字内容变得更具体、更有关系、更有仪式感。
- 物体让一次触碰比一次点击更有意义。

WhatMint 不做“把网页贴到物体上”。WhatMint 做的是让物体本身成为体验对象。

## 6. 时间与空间坐标

任何新产品都要先找到自己的坐标：它属于时间，还是空间？

属于时间的产品，回答：

我的人生留下了什么？

典型场景：

- 演唱会。
- 旅行。
- 毕业。
- 纪念日。
- 成长记录。
- 收藏作品。

属于空间的产品，回答：

这一刻，我想怎样存在？

典型场景：

- 桌面摆件。
- 窗边星空。
- 睡前表达。
- 出发仪式。
- 日常陪伴。
- 情绪安放。

时间让生命有长度。空间让生命有温度。

这个坐标不是分类游戏，而是帮助团队判断交互节奏、内容形态和商业入口：

- 时间类更适合长期保存、回顾、归档、版本和收藏。
- 空间类更适合当下回应、轻触发、氛围、陪伴和低负担复访。

## 7. OS 与应用边界

OS 负责承载意义，应用负责表达体验。

OS 应该负责：

- 上传。
- 创作。
- 内容管理。
- 权限。
- NFC 绑定。
- 物体身份。
- 触碰运行时。
- 内容容器。
- 事件记录。
- 作品模型。

应用应该负责：

- 一个具体物件。
- 一个真实行为。
- 一个独特人生问题。
- 一种可被记住的体验。
- 一套克制的表达方式。

不要让应用重复造轮子，也不要让 OS 去定义情感。OS 提供能力，应用形成意义。

## 8. 情绪强度与触碰频率

低频不等于弱产品，高频也不等于好产品。

有些应用低频但高强度：

- 毕业。
- 婚礼。
- 演唱会。
- 旅行归来。
- 重要礼物。

有些应用高频但轻情绪：

- 桌面陪伴。
- 桌面秘境。
- 睡前表达。

判断标准不是频率，而是：它是否在那个场景里不可替代。

## 9. 应用类型

WhatMint 的应用可以先分成三类。分类不是为了限制，而是帮助团队判断一个创意应该强调意义、行为还是状态。

系统字段：

- `applications.app_type = meaning`：意义型。
- `applications.app_type = behavior`：行为型。
- `applications.app_type = state`：状态型。

后续自营轻应用、联名场景入口或 manifest 接入时，也必须声明自己的 `app_type`。当前阶段不按开放第三方平台设计。

### 意义型应用

意义型应用回答人生问题。

它们强调记忆、表达、收藏和赠予。

示例：

- 纸巾小狗。
- 未来的纪念、传信或收藏作品方向。

### 行为型应用

行为型应用回答现实动作。

它们不一定诗意，但必须绑定具体物件，并让一个真实行为更轻、更稳、更有秩序。

示例：

- 未来按新核心重新接入的检查、保养或补充类应用。

行为型应用尤其要避免退化成泛工具。它们必须证明：为什么这个行为应该发生在这个物件上。

例如：

- 行李箱 x 检查 x 确认带齐。
- 相机包 x 检查 x 避免缺失关键装备。
- 咖啡机 x 保养 x 延长物件寿命。
- 洗手液瓶 x 补充 x 及时补齐消耗品。

### 状态型应用

状态型应用回应当下存在。

它们强调氛围、陪伴、空间感和轻触发。

示例：

- 桌面秘境。
- 未来按新核心重新接入的出发仪式、窗边星空或正念回应类应用。

一个产品也可能跨类型，但立项时必须先选择主类型。主类型不清楚，交互和内容就容易发散。

## 新应用立项卡

任何新应用进入开发前，先填写这张卡。

### 基础描述

- 应用名称：
- 一句话：物件 x 行为 x 意义。
- 目标用户：
- 典型场景：

### 八个立项问题

- 物件：这个体验依附在哪个实体上？
- 行为：用户为什么会拿起、触碰或靠近它？
- 意义：这一刻它完成什么人生表达？
- 小瞬间：它守住的是哪个容易被忽略的瞬间？
- 人生问题：这个应用只回答哪一个问题？
- 时间/空间坐标：它属于时间，还是空间？
- 实体不可替代性：没有这个物件，体验还成立吗？
- OS/应用边界：哪些交给 OS，哪些是应用独有体验？

### 评分

| 原则 | 评分 | 说明 |
|------|------|------|
| 物性 | 1-5 | 是否强依赖这个物件 |
| 行为 | 1-5 | 触碰动作是否来自真实生活行为 |
| 单一价值 | 1-5 | 是否只回答一个问题 |
| 微童话感 | 1-5 | 是否让小瞬间被轻轻认真对待 |
| 实体不可替代性 | 1-5 | 没有实体是否仍成立 |
| 时间/空间清晰度 | 1-5 | 坐标是否明确 |
| OS/应用边界 | 1-5 | 是否避免重复造轮子 |

建议：

- 总分 28 分以上：可以进入原型。
- 总分 21-27 分：继续收窄定义。
- 总分低于 21 分：暂缓开发。
- 物性低于 3 分：默认不做。
- 微童话感低于 3 分：默认继续重写产品动作和表达。

## 已删除旧应用的处理原则

答案之书、纪念瞬间、旅行轨迹和 Check 的旧代码、路由、页面和应用表不再作为活跃产品保留。它们可以作为未来产品方向重新讨论，但必须重新填写立项卡，并通过 `IP + 应用 + 实体入口 + 场景`、内容定义、OS 渲染协议和 Mint Studio 接入。

### 旧旅行轨迹的准入判断

旧版“旅行轨迹”暂不满足当前准入要求。

原因：

- 它容易变成旅行 App 的路线记录功能，物性不够不可替代。
- “旅行”是一个大场景，不应该由一个大而全 IP 承担。
- 触碰行李箱后“画出轨迹”的行为不如“出发前确认不遗漏”锋利。

建议重做方向：

- 拆成 `遗忘清单`：行李箱 / 行李牌 x 出发前检查 x 放心出门。
- 拆成 `纪念时刻` 或 `高光时刻`：门票 / 照片 / 纪念物 x 回看 x 留住瞬间。
- 如需联名旅行 IP，例如爱冒险角色，不做大旅行应用，而是替具体场景入口更换视觉、话术和资源表达。

## 最终判断

以后团队讨论新产品时，不只问：

这个点子好不好？

而是问：

它是否符合 WhatMint 的设计哲学？

如果一个创意能清楚回答“物件 x 行为 x 意义”，能证明实体不可替代，并且只回答一个人生问题，它就值得继续往前走。
