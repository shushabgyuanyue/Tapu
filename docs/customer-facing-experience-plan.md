# WhatMint 对客体验与 Mint Space 重构规划

本文用于冻结 WhatMint V1 对客叙事、用户状态路径和近期重构计划。它不改变核心 8 对象和 OS / 应用边界，而是把已经稳定的新核心能力包装成用户能自然理解的产品体验。

## 1. 产品判断

WhatMint 不是一个卖 IP 商品的平台，而是帮助用户打造属于自己的 **Mint Space** 的情感世界。

用户购买的不是一个摆件，而是邀请一个有灵的存在进入自己的世界。

因此，对客体验的主线是：

```text
发现世界 -> 邀请存在 -> 点亮 Mint Space -> 继续创造关系
```

## 2. 当前项目现状

### 已具备

- 核心对象已经收敛到 `users`、`ip_definitions`、`application_definitions`、`content_definitions`、`ip_instances`、`content_instances`、`resources`、`events`。
- `/api/assets` 已成为资产 / IP 实例的 OS 主入口。
- `/assets` 已从旧资产页拆成页面编排、`useAssetSpace`、`components/assets/*` 和 `styles/assetsSpace.css`。
- 纸巾小狗已能作为新核心样本，跑通 IP 实例、默认内容、内容定义、AR / 视频渲染和权限边界。
- 首页、商城、创作中心、内容详情和播放页已有可用基础，但对客叙事还没有全部统一到 Mint Space。

### 仍需收口

- 首页仍需要从普通营销页升级为“世界入口”。
- 商城需要从商品货架升级为“邀请新的存在”。
- NFC 触碰后的展示页需要承担线下冷启动，不应一上来强制注册或过度广告。
- 内容详情页应保持内容和 IP 实例绑定的清晰职责，不把过多 Mint Space 教育塞进去。

### 已收口

- 导航中的 `/assets` 入口已经对客显示为 Mint Space。
- `/assets` 首页已经升级为 Mint Space 三段结构：灵境合照、我的伙伴、灵境杂记，资产交易下沉到伙伴详情。
- `/assets/:instanceId` 已作为统一伙伴详情页承载体验、创作、默认内容、转赠和解绑；Mint Space 首页不再堆叠管理按钮。
- Mint Space profile 已统一由后端 OS 聚合生成，前端只负责渲染和交互，不再推导第二套空间人格。
## 3. 用户状态路径

### 未拥有用户

未拥有用户还没有“我的世界”，所以不应强推 Mint Space。

主路径：

```text
首页理解世界 -> 商城认识存在 -> 购买 / 获得实体 -> NFC 触碰体验 -> 绑定进入 Mint Space
```

导航倾向：

- 首页
- 邀请存在
- Mint Studio
- 登录

Mint Space 对未拥有用户只做轻量引导：解释“你的 Mint Space 还没被点亮”，提供去商城和输入 token。

### 已登录但未拥有

这类用户已经有账号，但还没有 IP 实例。

主路径：

```text
输入 token -> 接入第一个存在
或
进入商城 -> 邀请新的存在
```

导航倾向：

- 首页
- 邀请存在
- Mint Studio
- Mint Space

Mint Space 页面展示空态引导，不展示资产仓库式空列表。

### 已拥有用户

已拥有用户已经进入重度路径，Mint Space 应成为默认目的地。

主路径：

```text
Mint Space -> 我的伙伴 -> 体验 / 创作 / 邀请新伙伴 -> 灵境杂记
```

导航倾向：

- Mint Space
- 邀请新伙伴
- Mint Studio
- 账户

管理能力存在，但降级到伙伴详情和二级操作中，不抢占世界表达。

## 4. 对客入口矩阵

### 首页

定位：世界入口。

回答：

> 这里是什么，正在发生什么？

结构：

- 品牌展示 + 活动展示：解释世界为什么存在，并证明它正在发生新相遇。
- 存在展厅：展示可以被邀请进入生活的 IP。
- Mint Space 展示：展示拥有之后的个人世界是什么样。
- 创作示例：展示关系可以继续被赋予意义。

首页不承担资产管理，不把商城做成第一屏货架。

### 商城 / IP 详情

定位：邀请新的存在。

回答：

> 我的世界还能遇见谁？

商城列表保持干净，不需要额外放快捷 Space 入口。用户想绑定或进入 Space，可以直接点导航。

IP 详情承担：

- IP 设定
- 实体信息
- 应用体验
- NFC 说明
- 购买 / 邀请
- 与其他 IP 的关系

### NFC 触碰展示页

定位：线下冷启动入口。

回答：

> 我碰到的这个物是什么，它为什么有数字体验？

未绑定时：

- 先展示体验。
- 再克制引导“接入你的 Mint Space”。
- 提供“了解 WhatMint”入口。

已绑定后：

- 基本不打广告。
- 保留轻量 Mint Space 导航。
- 优先服务用户本次触碰体验。

### Mint Space

定位：拥有后的个人世界入口。

回答：

> 我的世界是什么样？

结构：

- 灵境合照：用户和已拥有 IP 共同形成的视觉名片。
- 我的伙伴：用户拥有的 IP，进入详情、体验、创作、赠送、解绑。
- 灵境杂记：关系碎片和世界观短文，不是日志，也不是任务。

### Mint Studio

定位：赋予存在新的意义。

回答：

> 我还能为这个存在创造什么？

Studio 不回退为管理表单。它负责内容创建和修改流程编排，长期维护交给内容详情和伙伴详情。

### 内容详情

定位：内容资产查看与维护。

回答：

> 这个内容是什么，它绑定到哪个存在？

内容详情主要处理内容和 IP 实例绑定，不引入过多 Mint Space 教育。绑定完成后可以轻量引导“去 Mint Space 看看这个伙伴”。

## 5. Mint Space 页面目标结构

### 顶部：灵境合照

- 展示用户的 Mint Space 视觉名片。
- 中心是抽象用户形象。
- 周围是已拥有 IP。
- 氛围根据 IP 组合生成：光线、天气、色调、装饰。
- 第一版使用后端 OS 规则化 profile，不需要立即接 AI 生成；前端不展示难以理解的内部计算标签。

操作：

- 分享 Mint Space。
- 邀请新的存在。

### 中部：我的伙伴

- 横向滑动展示用户拥有的 IP。
- 每个伙伴展示形象、名称、一句状态。
- 点击进入对应 IP 伙伴详情。

伙伴详情承载：

- IP 介绍。
- 当前实例信息。
- 使用应用。
- 创作内容。
- 默认内容。
- 赠送 / 解绑。

### 底部：灵境杂记

- 展示极简文字卡。
- 来源可以是用户拥有 IP、IP 官方关系和高价值事件的规则化组合。
- 不直接展示操作日志。
- 不追求频繁更新。

示例：

> 你的 Mint Space 里现在住着三位朋友。

> 纸巾小狗总喜欢靠近答案之书，因为它发现很多悲伤来自没有想明白的事情。

## 6. 重构顺序

### Phase 1：文档与导航口径冻结

- `SPEC.md` 写入 Mint Space 北极星。
- `product-manifesto.md` 写入“存在 / 邀请 / Mint Space / 创造”的用户叙事。
- `AGENTS.md` 写入 Mint Space 优先重构规则。
- `asset-space-core-verification.md` 改为 Mint Space 验收口径。

### Phase 2：首页重构

- 首页改成四段式世界入口。
- 首页不直接变商城。
- 活动和品牌共享第一屏权重。
- IP 展示使用“存在 / 伙伴 / 居民”叙事。

### Phase 3：Mint Space 重构

- `/assets` 保持路径兼容，但页面命名与体验升级为 Mint Space。
- 未拥有用户看到点亮引导。
- 已拥有用户看到灵境合照、我的伙伴、灵境杂记。
- 管理能力下沉到伙伴详情或二级操作。
- 资产交易只走 `/api/assets`，不在 `/api/auth` 保留资产兼容壳。

### Phase 4：商城与 IP 详情口径重构

- 商城从商品货架改为“邀请新的存在”。
- 商品列表不塞 Space 快捷入口。
- IP 详情解释存在、关系、体验和邀请方式。

### Phase 5：NFC 展示页冷启动重构

- 未绑定 token 先给体验，再引导绑定或了解品牌。
- 已绑定 token 几乎不打广告，只保留轻量导航。
- 播放 / AR / Web 内容继续走 OS 渲染协议。

### Phase 6：Studio 与内容详情收口

- Studio 文案从“上传/编辑”转为“赋予存在新的意义”。
- 内容详情保持内容维护和绑定职责，不扩大成 Space 教育页面。

## 7. 开发约束

- 不新增核心表来表达 Mint Space；它是由核心对象聚合出来的页面和体验范式。
- 不把任务、等级、抽卡、成长数值作为第一版主表达。
- 不把商业入口做成硬广告；购买是邀请，绑定是接入，资产是伙伴。
- 非管理端新文案必须进入 `src/copy/*`。
- 新接口必须进入 `routePermissions + operation + contract`。
- 触碰体验优先展示内容，再解释品牌。

## 8. 验收标准

完成后，用户应该能自然理解：

- WhatMint 是一个会不断发生新相遇的世界。
- IP 是可以被邀请进入生活的存在。
- 拥有之后会形成自己的 Mint Space。
- 创作不是管理内容，而是让关系继续生长。
- 线下拿到实体的人，可以先体验，再被温和引导进入 Mint Space。

## 9. Mint Space 剩余高收益待办

### 必须继续收口

- 合照数据：`mintSpaceProfile` 已经能输出人格轴、氛围和布局提示；下一步需要让 IP 定义明确填写 `space_profile`，包括空间特质、人格轴修正、角色状态句和视觉锚点。
- 关系矩阵：当前杂记支持读取 `ip_definition_relation_links`，但真实官方关系内容还需要在官方管理或 seed 中补齐，避免长期依赖规则兜底。
- 空态路径：未拥有用户进入 Mint Space 时，继续优化“输入 token”和“探索新的存在”的优先级与视觉权重，但不得回退为空资产列表。

### 可以延后

- AI 生成合照和杂记：第一版用规则化 profile 即可；AI 只应该替换表达层，不应该成为空间归属和关系事实的来源。
- 实时事件驱动杂记：V1 可以用持有 IP 和官方关系生成低频杂记，等 Event Engine / Skill Runtime 更稳定后再接入动态事件。
- 社交分享卡：需要等合照视觉稳定后再做，否则容易把半成品视觉扩散出去。

### 已冻结的设计判断

- 伙伴详情采用 `/assets/:instanceId` 独立页。它更适合深链、移动端和后续单个 IP 实例的 OS 能力扩展。
- IP 空间人格轴是完全配置化，还是“默认规则 + IP 定义修正”。当前建议后者：OS 有默认推导，官方只填差异项，降低配置成本。
- 购买记录不进入用户侧 Mint Space。购买发生在外部平台，订单记录属于支撑域或账户/运营侧信息，不应占用灵境首页权重。
